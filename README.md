# TURRIT 任务助手

原生 Android 项目，使用 Kotlin + Jetpack Compose。目标设备为 MuMu Android 12 和普通 Android 手机。

## 当前版本

- 版本：`0.3.2-alpha13`
- 阶段：第三阶段——XLSX/头像 ZIP 导入、顺序预览与 Turrit 界面资料操作
- 主界面：账号管理、群组任务（资料入口已并入账号管理）
- 本地账号数据：SQLite
- GitHub Actions：手动触发或主分支代码变更后构建 Debug APK

## 当前已实现

### 第一阶段

1. 原生 Compose 主界面，底部保留“账号管理”和“群组任务”两个入口。
2. 账号列表改为单行姓名 + 复选框，选中行使用浅蓝底色。
3. 账号页支持导入 XLSX 和头像 ZIP、下载顺序模板、按已勾选账号顺序预览资料分配。
4. 空白字段保持不变，`【清空】` 才执行清空；新模板的「姓名」写入名字栏，姓氏默认清空。
5. 资料执行通过 Turrit 可见界面操作；无法识别字段或按钮时暂停等待人工处理。
6. GitHub Actions 先运行单元测试，再构建 Debug APK。

### 第二阶段

1. 扫描设备中可启动的应用，自动识别名称/包名包含 `Turrit` 的分身及已知包名 `org.telegram.group`。
2. 可手动从已安装启动器应用中选择名称不同的 Turrit 分身。
3. 增加用户主动开启的 AccessibilityService。
4. 用户选择某个 Turrit 分身后，服务只读取该应用当前可访问界面中的手机号及附近文本。
5. 识别结果保存在本地 SQLite，账号列表支持选择、全选、取消。
6. MuMu Root 环境下额外尝试通过 `su -c "pm list packages -3"` 枚举已安装的 Turrit 相关应用；无 Root 或命令失败时回退到 PackageManager 启动器扫描。
6. 页面已移除标题下方的解释性小字，GitHub Actions 使用 `android-actions/setup-android@v4`。
7. 账号识别、账号管理和资料批量修改入口合并在同一页面；资料表格和头像 ZIP 在本地解析，不上传服务器。

## 账号识别使用方式

1. 打开“账号管理”，点击“扫描 Turrit 应用”。
2. 自动识别不到的分身，可点击“手动选择”。
3. 点击“开启识别”，在系统无障碍设置中启用“TURRIT 账号识别”。
4. 返回软件，对目标分身点击“识别账号”。
5. 在 Turrit 中打开账号切换列表或手机号可见的页面；必要时滚动列表。
6. 返回助手查看识别结果，完成后点击“停止”。

## 重要限制

- 普通 Android 应用不能直接读取 Turrit 私有数据库。
- 无障碍服务只读取用户主动选择的 Turrit 应用中可访问的界面文字。账号切换列表中的姓名可以被读取时会先保存姓名；被隐藏、遮挡或未暴露给无障碍节点的手机号不会被猜测。
- 姓名和用户名是根据附近可见文本进行关联，必须在实际设备和 Turrit 版本上验证。
- 账号列表中的“启用/暂停”只控制本工具，不代表 Telegram 平台限制状态。
- 资料 UI 自动化根据 Turrit 当前可访问控件文字定位；不同 Turrit 版本的编辑页控件可能不同，未识别到输入框/保存按钮时会暂停，不会猜测点击。
- 头像文件先写入系统图库，再通过 Turrit 的照片选择界面选择；图库控件未暴露可访问节点时需要人工处理。
- 任务进度目前保存在应用进程内；系统强制结束进程后不能保证自动恢复。
- 识别结果只保存在本地，不上传服务器。

## GitHub Actions 构建

1. 将整个 `TURRIT-Assistant` 目录内容上传到仓库根目录。
2. 推送到 `main` 或 `master`，或在 GitHub Actions 手动运行 `Android Debug APK`。
3. 成功后下载 `TURRIT-Assistant-debug` Artifact。
4. 首次运行还会上传 `TURRIT-Gradle-Wrapper` Artifact；如仓库没有标准 Wrapper JAR，可下载后补入仓库。

构建配置：JDK 17、Gradle 8.11.1、Android Gradle Plugin 8.9.1、Kotlin 2.1.10、Android SDK 35。

## 本地构建

需要 JDK 17、Android SDK 35 和网络连接：

```bash
chmod +x ./gradlew
./gradlew :app:assembleDebug
```

当前 ZIP 中的 `gradlew` 是轻量下载启动脚本，不冒充官方 `gradle-wrapper.jar`。GitHub Actions 会生成官方 Wrapper 并单独上传。

## 本次修复：账号列表边界与滚动识别（0.2.2-alpha05）

- 参考 `活跃jisou.zip` 的账号识别实现：以「添加账号」作为账号列表底部边界，只读取该按钮上方的账号行。

- 改用无障碍手势完成列表回顶、逐屏向下扫描和有限次数回扫；不再依赖 Turrit 是否暴露 `ACTION_SCROLL_FORWARD`。
- 根据 Turrit 的 `x/10` 账号计数、可见账号名称和屏幕位置签名判断进度；达到数量或到达滚动边界后自动结束。
- 扫描结束后自动返回 TURRIT 任务助手账号页面，更新识别状态并显示结果。
- 启用无障碍手势权限。
- 初始化数据库时自动清除旧版本误保存的「添加账号」「Add Account」姓名记录；不会删除真实账号。
- 账号姓名来自 Turrit 当前可访问界面；账号列表没有展示手机号时，手机号字段继续留空。


## 本次修复：代理等待与完整账号扫描（0.2.2-alpha06）

- 识别前检查 Turrit 活动窗口；短暂无障碍窗口切换不再直接判定为离开前台。
- 检测到「正在连接代理」「代理连接失败」时暂停点击和滑动，定时检查；代理状态消失并连续稳定后再继续。
- 代理连接最长等待 180 秒；Turrit 活动窗口切换最长等待 90 秒。
- 账号列表滑动手势严格限制在「个人资料标题下方、添加账号按钮上方」的列表区域，不再滑入添加账号行和下方菜单。
- 根据实际可见列表变化判断是否已经回到顶部，避免固定次数无效滑动。
- 扩大向下扫描次数，直到读取到 Turrit 显示的账号数量，或确认到达列表边界。
- 识别页面显示「等待代理连接」「正在确认代理连接」等当前状态。
- APK 页面超时等待同步延长至 210 秒。


## 账号扫描改进（0.3.1-alpha09）

- 参考活跃 jisou 的流程：确认底部导航、打开账号列表、回到列表顶部、逐屏向下扫描、反向补扫。

### 测试版安装说明（0.3.2-alpha10）

- 本版测试包使用独立包名后缀 `.test2`，不会覆盖此前的 `.test` 测试版，旧测试版数据保留。
- 新测试包首次安装后需要重新识别账号、重新勾选账号并重新导入资料表格/头像 ZIP；应用不会读取另一个包名的私有数据。
- GitHub Actions 从本版开始缓存稳定的 debug 签名密钥，后续继续使用 `.test2` 包名的测试 APK 可直接覆盖升级。


- `.test2` 测试包使用项目内专用测试签名密钥（仅用于 debug 测试，不能用于正式发布）；后续测试构建保持同一签名，可覆盖升级并保留该测试包本地数据。
